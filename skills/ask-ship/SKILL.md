# Какой сценарий spec-ship брать

Определи ветку по входу пользователя, назови команду с аргументами, объясни выбор в 2–3 строках. Всё нужное — здесь; другие `SKILL.md` не читай.

## Развилка по входу

| Что на входе | Команда | Почему |
|---|---|---|
| Симптом: падающий тест, «не та сумма», регрессия | `/spec-ship:bug-fix «симптом; репро; якорь»` | Заменяет shape-doc+decompose. Ищет корень, не место симптома |
| Понятная фича, одно требование | `/spec-ship:run «описание»` | Вся цепочка одним вызовом, остановки только на гейтах |
| Фича меняет существующий код, но неясно какой | `/spec-ship:survey «якорь»` → потом `run` | Трассировка даёт контекст интервью и sibling-callers |
| «Такой же, как X, только для Y» — клон паттерна | `/spec-ship:run «…»; якорь «эталонный символ» --auto-decompose` | Якорь обязателен: через survey подтянет workflow-доки эталона и оттрассирует только отличия |
| «Такой же, но формула/фильтр другой» — дельта | `/spec-ship:run «…»; якорь «эталон»; дельта: «что иначе»` | Канон — база, трассируется только отличие. Слайс дельты может встать на шейп как LOGIC |
| Эпик: несколько фич, решения сцеплены, туман | `/spec-ship:roadmap «цель эпика»` | Карта решений над пайплайном; выпускает созревшие фичи в `run` |
| Одна мелкая задача, спека уже в голове | `/spec-ship:build task-NNNN-NN` | `run` не окупается — нужен готовый TaskSpec |
| Требование есть, но контроль на каждом шаге | этапы по очереди (см. ниже) | Дороже вызовами, дешевле по риску |
| Фича смёржена, знание надо в канон | `/spec-ship:adr-promote`, `/spec-ship:doc-promote-feature` | Решения → ADR, поведение → workflow-доки |
| Код есть, доков нет | `/spec-ship:doc-backfill` | Workflow-доки из survey, без MR-гейта |

## Ручная цепочка

```
survey → shape-doc → decompose → build (×N задач) → review
```

Вызывать по очереди, когда нужен контроль между этапами. `run` делает то же самое, но без ручных переключений.

## Гейты — где вас всё равно спросят

Апрув спеки · апрув разбивки · шейп LOGIC · CRITICAL целиком на человеке · эскалации build · `review: ESCALATE`.

Флаги `--auto-shape` / `--auto-decompose` / `--auto` снимают низкорисковые гейты у `run`.

## Частые ошибки выбора

- **`shape-doc` на баге** — интервью выродится в «хотим правильное поведение». Бери `bug-fix`.
- **`run` на эпике** — размытая цель даст спеку-кашу. Сначала `roadmap`.
- **Новый ADR после клона** — решение то же, что у эталона. Промоутить только если клон **изменил** паттерн.
- **`roadmap` на одной фиче** — карта решений из одного узла. Сразу `run`.
- **`run` ради экономии токенов** — этапы выполняются те же. Выигрыш в вызовах, не в токенах. Окупается на 3–15 слайсах.
- **`survey` пропущен на баге** — там он обязателен, не опционален.

## Экономика прогона

Дороже всего — холодный старт: трассировка и интервью с нуля. Дешевле — переиспользовать канон.

- **Якорь на существующий код** тянет `current`-доки из `.ship/docs/workflows/` через survey. Без якоря survey не запустится, и паттерн-доки никто не подхватит.
- **ADR-решения** (`.ship/docs/adr/`) доезжают сами — их читают shape-doc, decompose, review.
- **Клон без якоря** — главная потеря. «Сделай такой же» выглядит как новая фича, уходит в `run` как greenfield, и workflow-канон эталона никто не подхватывает: decompose выводит файлы из головы. Клон — это изменение существующего поведения, у него всегда есть якорь.
- **Область скоро получит фичи, доков нет** → `survey` эталона + `doc-backfill` заранее. Разовая инвестиция, окупается со второй задачи.
- **Сомневаешься, гейт или нет** → гейт. Лишний апрув дешевле спеки, замороженной в тумане.

## Дальше

Когда сценарий выбран: детали этапа — его `SKILL.md` в `.claude/skills/spec-ship/{скилл}/`; сквозные протоколы и схемы — `skills/README.md`.
